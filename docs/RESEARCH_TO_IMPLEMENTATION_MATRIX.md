## 1. Methodology & Classification Principles

This matrix reconciles published scientific literature and security benchmarks against the actual ChronoCongiSec / Agent Memory Security Center (AMSC) codebase.

### 1.1 Method Fidelity Definitions
- **FAITHFUL:** The implementation strictly follows the source paper's algorithms, theoretical assumptions, data representations, and evaluation protocols without behavioral degradation.
- **ADAPTED:** The source methodology is intentionally modified to satisfy enterprise constraints (e.g. converting batch research scripts to real-time ASGI middleware, substituting synthetic benchmarks with enterprise policies). All adaptations must be explicitly justified.
- **INFRASTRUCTURE:** General-purpose software engineering that provides the execution foundation for a research method (e.g. databases, HTTP gateways, W3C tracing, thread pools) but is not itself the research contribution.
- **ORIGINAL:** AMSC-developed architecture or novel algorithm without a published peer-reviewed precursor.
- **HYPOTHESIS:** Proposed concept or heuristic awaiting empirical validation on representative corporate datasets.
- **NOT_APPLICABLE:** Academic literature cited for background context or survey taxonomy whose methodology is outside the operational boundary of AMSC.

### 1.2 Non-Negotiable Evidentiary Rules
1. **Existing gateway infrastructure does not prove faithful implementation:** Generic FastAPI routing or standard dictionary filters do not constitute a faithful implementation of formal policy enforcement or temporal memory papers.
2. **Research-reported results are not AMSC results:** Benchmark metrics published in external papers (e.g. AgentPoison's >80% ASR, MPBench's 50.46% ASR, KnowledgeLine's 100% accuracy claims) must never be reported as AMSC performance without independent, reproducible local testing.
3. **No conflation of distinct concepts:**
   - **ChronoMem (Yadla 2025)** is temporal multimodal memory for agentic navigation and QA; it is **NOT** an execution recovery or cryptographic rewind algorithm.
   - **AgentRewind (Zhuang et al. 2026)** is an execution recovery and context-checkpointing method for long-horizon agents, distinct from database snapshotting.
   - **Dual Trace** is an **ORIGINAL** AMSC architecture pattern pairing cognitive fact lineage with execution scenes; it is not borrowed from any single academic paper.

## 3. Fidelity Assessment & Implementation Plan Summary

### 3.1 Genuine Implementations (Faithful & Adapted)
1. **Wang et al. (R-005 - MCP Policy Enforcement):** The deterministic Gateway in `backend/app/api/gateway.py` faithfully implements the paper's central concept: complete mediation at the tool boundary, deterministic parameter ceilings, fail-closed policy logic, and append-only audit chaining.
2. **MemLineage (R-008 - Provenance Traversal):** `backend/app/memory/provenance.py` and `traversal.py` faithfully enforce directed acyclic graph (DAG) invariants, cycle rejection, and strict resource budgets (depth, node count, edge count).
3. **Dual Trace (O-001 - Original Architecture):** The W3C-correlated Dual Trace engine in `backend/app/api/traces.py` successfully unifies execution lane telemetry with memory retrieval events.

### 3.2 Addressed Misconceptions & Differentiations
- **ChronoMem vs. Rewind:** The codebase's `ChroniMem` router (`backend/app/api/chronimem.py`) is a chronological version-comparison utility (`diff` between versions). It is not an implementation of Prasanth Yadla's multimodal memory architecture (R-004), nor is it an execution recovery engine. True execution recovery is governed by `backend/app/recovery/orchestrator.py` (adapted from AgentRewind, R-003).

### 3.3 Required Future Research Work (Phases 2 & 3)
1. **Phase 2 (MPBench R-002):** Implement explicit write-channel tagging on `MemoryIngestRequest` and deploy channel-specific integrity checks.
2. **Phase 2 (AkasicMEM R-008):** Add HMAC cryptographic signing over memory versions to prevent double-tampering of content and SHA-256 digests.
3. **Phase 3 (TrustMem R-010 & DeBERTa NLI):** Deploy local ONNX DeBERTa-v3 cross-encoder to perform source-grounded claim entailment verification.
