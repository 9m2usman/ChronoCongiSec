## Day 1 — Schema DDL + first Alembic migration (2026-11-17)

**Built**
- `backend/app/database/base.py`: declarative `Base`, constraint naming convention, column helpers (`id_column`, `tenant_id_column`, JSONB defaults).
- `backend/app/database/session.py`: async engine and session factory. Only the `postgresql+asyncpg` driver is accepted.
- `backend/app/database/models/`: 36 tables in six modules (identity, agents, memory, gateway, recovery, observability). `GLOBAL_TABLES = {tenants, users, permissions, role_permissions}`; `roles` is the only table where `tenant_id` may be NULL.
- `backend/alembic.ini`, `backend/alembic/env.py` (async), `backend/alembic/versions/0001_initial_schema.py`. The DB URL is never stored in `alembic.ini`.
- `backend/requirements.txt`: added `alembic==1.20.1`.
- Tests in `backend/tests/database/`: `test_migrations.py`, `test_schema_rules.py`, `test_tenant_enforcement.py`, plus `helpers.py` and `conftest.py`. Each test creates its own `amsc_test_<random>` database and drops it afterwards.

**Why**
- DOC-006 Day 1 M6 row: "Schema applies cleanly to blank database".
- DOC-005 §3 DDL is copied faithfully, including plain single-column FKs. Composite tenant FKs come on Day 2 (DOC-005 §1).
- HARD RULE: every tenant-owned table has `tenant_id NOT NULL` with an FK to `tenants.id`.

**Test result**
- `pytest backend/tests/database -v`: **13 passed**. Full suite `pytest -q`: **187 passed** (174 existing + 13 new).
- Proof (break it and see):
  1. Made `agents.tenant_id` nullable in both the model and the migration. `test_tenant_id_is_not_null_except_global_roles` and `test_insert_without_tenant_id_is_rejected` FAILED.
  2. Restored the migration but left the model nullable. `test_models_match_migrated_schema` FAILED with `modify_nullable agents.tenant_id`.
  3. Restored both files: 13 passed again. No temporary databases left behind.

**Problems and fixes**
- Python 3.14.7 is the only system Python, and `asyncpg==0.29.0` has no 3.14 wheel. Fix: installed Python 3.12.16 with `uv python install 3.12` (user-level) and created `.venv` with it. `requirements.txt` is unchanged apart from the alembic line.
- `ImportError: greenlet` on the first `alembic` run. SQLAlchemy 2.1 no longer installs greenlet automatically, and the async extension needs it. Fix (local only): `uv pip install greenlet`. **`requirements.txt` still needs `greenlet` (or `sqlalchemy[asyncio]`); waiting for approval because it goes beyond the alembic line.**
- `Index(..., occurred_at.desc())` cannot be used inside the class body. Moved the `idx_audit_tenant_occurred` definition below the class.
- The migration was autogenerated against a scratch database (`amsc_m6_autogen`, dropped afterwards), then reviewed against DOC-005 by hand. The dev database `amsc` was never touched.
