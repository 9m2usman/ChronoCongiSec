## Day 2 — Composite tenant constraints and indexes (2026-11-17)

**Built**
- `backend/alembic/versions/0002_composite_tenant_foreign_keys.py` (hand-written, data-driven):
  - `UNIQUE (tenant_id, id)` on the 12 referenced parent tables.
  - 37 composite FKs `(tenant_id, <col>) -> parent (tenant_id, id)`, replacing every plain FK between tenant-owned tables.
  - `ON DELETE SET NULL (<col>)` (PostgreSQL 15+), so deleting a parent clears only the reference and never `tenant_id`.
  - `(tenant_id, <col>)` index for every composite FK, except where a DOC-005 index or a UNIQUE constraint already covers it.
  - Trigger `trg_forbid_tenant_id_change` on all 32 tables with `tenant_id`: any UPDATE that changes `tenant_id` is rejected.
- `backend/app/database/base.py`: `tenant_parent_key()` and `tenant_fk()` helpers. Models now declare the same composite FKs, so the drift test still compares them.
- `backend/app/database/repositories/base.py`: `TenantScopedRepository` (get/list/add/update/delete). It is always filtered by the bound tenant, `add()` stamps `tenant_id`, `update()` refuses `id`/`tenant_id`, `list()` is bounded to 500 rows, and it never commits.
- Tests: `relationships.py` (an independent list of the 37 expected relationships), `factory.py` (a schema-driven row factory), `test_cross_tenant_fks.py`, `test_repositories.py`, and new rules in `test_schema_rules.py`. `conftest.py` gained a per-module database plus transaction-rollback fixtures (`tx_conn`, `session`).

**Why**
- DOC-006 Day 2 M6 row: "Cross-tenant foreign key inserts fail in DB".
- DOC-005 §1: tenant-safe relational references must be enforced in the database. DOC-005 §4.1: repository row scoping.
- GAP-003 (DB layer) and GAP-017 (tenant-consistent composite FKs).

**Deliberate deviations from the DOC-005 DDL (all stricter)**
- `policy_decisions.incident_id` now has a composite FK to `incidents` (DOC-005 leaves it unconstrained).
- `trace_spans.parent_span_id` stays a **soft reference** (no FK) because OpenTelemetry often delivers a child span before its parent. It is listed in `SOFT_REFERENCES`.
- `tenant_id` is immutable (trigger). DOC-005 does not say this explicitly; it follows from "does not create cross-tenant links".

**Test result**
- `pytest backend/tests/database -v`: **250 passed** (~30 s). Full suite `pytest -q`: **424 passed**.
- For each of the 37 relationships: same-tenant insert accepted, forged cross-tenant insert rejected, missing parent rejected, forged cross-tenant UPDATE rejected, and CASCADE/SET NULL delete behaviour verified. All 32 `tenant_id` tables reject a tenant change.
- Proof (break it and see):
  1. Replaced the `memory_versions.record_id` composite FK with a plain FK (model + migration). 4 FAILED: the forged insert and the forged update for that relationship, the composite rule and the exact-relationship list.
  2. Emitted plain `SET NULL` (without a column list) for the `agent_id` FKs. 6 FAILED: 4 delete-behaviour tests (the delete tried to null `tenant_id`), the SET NULL rule and the model/migration drift test.
  3. Restored both files: 250 passed again. No temporary databases left behind.

**Problems and fixes**
- Autogenerated 0002 emitted the operations table by table, so a composite FK was created before its parent `UNIQUE (tenant_id, id)` (Postgres error: "no unique constraint matching given keys"), and the downgrade dropped parent keys while FKs still used them. Fix: rewrote 0002 by hand as frozen data. All parent keys are created first and dropped last.
- asyncpg returns `pg_constraint.confdeltype` (`"char"`) as `bytes`. `test_relationships_match_expected_list_exactly` failed with `KeyError: b'c'`, and **`test_set_null_references_never_clear_tenant_id` was passing vacuously** (`b'n' != 'n'` skipped every row). Fix: cast to `::text` in SQL, and added "rows actually checked" guards to both rule tests so a silent skip now fails.
- Runtime: ~200 tests that each created their own database would take minutes. Fix: one migrated database per module, and every test runs inside a transaction that is rolled back (savepoints for expected failures).
